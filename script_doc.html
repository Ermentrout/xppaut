XPPAUT scripting: a short manual

A script is a plain text file of commands that XPPAUT carries out for you: set parameters and numerics, press menu keys, answer dialogs, move around AUTO diagrams, and save figures. Use it to reproduce a figure exactly, to run a tutorial with pauses, or to run unattended. You do not have to write a script by hand: XPPAUT can record what you do as a script (section 11).

1. Running a script

xppaut model.ode -script file.xps                          # pauses and waits are honoured
xppaut model.ode -script file.xps -nopause                 # skip pause / wait / speed
xvfb-run xppaut model.ode -script file.xps -scriptexit     # unattended; exits when finished
  • The script needs the graphical interface. (It is ignored with -silent.)
  • XPP stays open when the script ends, unless you gave -scriptexit or the script says quit.
  • -scriptexit implies -nopause, so an unattended run can never wait for a person.
  • From inside the program: File → Do script (key d) opens a file selector (*.xps) and runs the file you choose. Pauses are honoured and errors appear in a box. A script cannot start another script.
  • A script with no pause runs straight through.
  • Recording: File → recOrd script (key o) writes a script for you as you work. See section 11.

2. The script file

One command per line. # starts a comment when it is at the start of a line or follows a blank (keys i g # run it). To use a literal #, quote it: msg "step #1". Command names are not case sensitive. A file is checked completely before anything runs, so a typo on line 40 stops the script before line 1 is executed.

3. Commands

Command What it does
set a=2.5;b=0.2;total=40;xlo=-10 Sets parameters, initial conditions, numerics, AUTO and plot options. Same syntax as a parameter set; separators are ; , or blanks.
print a Writes a parameter, variable or initial condition to the terminal.
keys i g Presses keys in the main window.
autokeys r s Presses keys in the AUTO window (open it first with keys f a).
browser open / browser close Opens the data browser (the Data button) or closes it with its Close button (section 7).
browsekeys down down f Presses keys in the data browser (section 7).
aplot fit Presses a button of the array plot window: edit fit range redraw print gif surface close (section 8).
ans ... Answers the next dialog (section 4).
ok Presses OK on the next dialog, keeping what it shows.
cancel Cancels the next dialog.
auto goto HB 1 Selects a point in the AUTO diagram (section 6).
auto list Prints the labelled points of the AUTO diagram.
msg "text" Shows text in the info bar and on the terminal. With -nopause it goes to the terminal only, so it never appears in a final picture.
pause ["text"] Waits for Enter or Space (Esc stops the script). Skipped with -nopause.
wait 2.5 Waits that many seconds. Skipped with -nopause.
speed 0.2 Delay between keys, so an audience can follow. Skipped with -nopause.
shot fig.ps Saves the plot to a file (.ps or .svg) without going through the dialogs (section 5). shot auto d.ps saves the AUTO diagram.
for a in 1 2 3 ... end Repeats the lines between, with $a replaced by each value (section 9). Also for a = 0:0.5:2 and repeat 3.
try ... else ... end Carries on after a failure: if a command between try and else fails, the else part runs and the script continues (section 10). $error holds the message.
quit Leaves XPPAUT.
click x y / drag x1 y1 x2 y2 Supplies the mouse for a command that waits for it: placing text, the zoom rectangle, an arrow (section 4).

set

set leaves XPP in the same state as making the changes by hand: tables and derived parameters are recomputed, the plot window and the plotted variables (xp=x;yp=y) are updated, and the parameter and IC boxes are redrawn. Two things are refused: maxstor (fixed when XPP starts), and any name XPP does not know (the script stops with the line number).

keys

Tokens are separated by blanks. A token can be

  • a named key: enter tab esc space bksp del up down left right home end pgup pgdn;
  • a single letter. Menu hot keys are all lower case, so a capital is sent as lower case (keys I G is keys i g);
  • any other text, typed exactly (keys 0.5 enter), or a quoted string (keys "Fig 1").

Keys are delivered one at a time, only when XPP is idle, so a key never races a redraw. A run started by keys i g finishes before the next line is read. The hot key of a menu item is the capital letter in its name (Initialconds → i, nUmerics → u, Graphic stuff → g).

Keys used in this manual: i g run, i l continue from the last point, w w window form, n n nullclines, g p PostScript, g v SVG, e erase, v 2 2D view dialog, f a open AUTO, f g then a letter loads a stored parameter set, v a array plot, f o start or stop recording.

4. Dialogs: ans, ok, cancel

A dialog asks the script for its answer before it opens, so the answer goes on the line after the keys that opens it.

Dialog What you write
One line (command bar, one-field box) ans text
File selector ans filename.ps
Form with several fields answer by position or by label, with the fields separated by a vertical bar (examples just below)
Yes / no ans y or ans n
Accept as shown ok
Cancel cancel
Let the person type this one ans ? (not allowed with -nopause)

Form answers, written exactly as you type them (the | is a vertical bar):

ans 0|10|-2|2                 # by position; an empty field keeps its value
ans ||24||25                  # change only fields 3 and 5
ans X Lo=0|Y Hi=2             # by label; fields you leave out keep their values

Labels must match the dialog's text (case does not matter); a label that matches no field is an error. Fields in a form hold at most 24 characters. Postscript opens two dialogs, the options form and then the file name, so it needs two lines. A dialog with no answer line is left open for the following keys lines to drive.

If a dialog changes

Scripts read each dialog's field list when it opens, so changing a dialog does not require changing the scripting program. What it can mean for a script you wrote earlier:

  • A field added at the end: nothing changes. Answers by position or by label still work, and the new field keeps its default.
  • A field inserted in the middle: answers by label still work; answers by position shift and put values in the wrong fields, with no error. Use labels (ans Axes fontsize=24|Linewidth=25) for dialogs that may change. ok is never affected.
  • A field renamed: an answer by that label stops with an error that names the dialog and lists its current fields. (A value that really contains = can be quoted: "a=b".)
  • A new dialog added to a menu action: the new dialog opens with no answer waiting, so add an ok or ans line for it. The script then stops with an error if you forget, rather than doing something wrong. The reverse, a dialog that no longer appears, makes the old ans line an error ("ans has no prompt to answer").

Mouse waits: click and drag

A few commands wait for the mouse in the plot window: placing text, a start point chosen with the mouse, a freeze key, and, with a drag, the zoom rectangle and arrows. The line after the keys that start one supplies the mouse:

click x y               a point, in the data coordinates of the plot
drag x1 y1 x2 y2        a rectangle or a line, from the first point to the second
click pixel x y         the same, in window pixels (also drag pixel x1 y1 x2 y2)
click ?   drag ?        leave this one to the person at the keyboard
                        (not allowed with -nopause)

Examples (osc.ode):

keys t t                # Text, etc -> Text
ans hello               # the text
ans 2                   # its size
click 8 1.5             # where it goes: t = 8, x = 1.5

keys w z                # Window/zoom -> Zoom in
drag 5 -1 15 1          # the new window: t from 5 to 15, x from -1 to 1

For a zoom the first point becomes (xlo, ylo) and the second (xhi, yhi), as with the mouse. Data coordinates are those of the plot that is showing when the click happens, so a script that changes the window first should click after it. A point outside the plot window is an error, as a real click could not be there.

Some waits repeat until Esc. Initialconds → mIce (keys i i) takes a click, runs from that point, and asks for the next one. Give it one click line for each start and end it with keys esc, which ends a mouse wait as Esc does for a person:

keys i i
click 1 1
click -1 0
keys esc

If the script has nothing to give a mouse wait (no click or drag line after it), an unattended run (-nopause, -scriptexit) stops with an error that names the line, instead of waiting for ever:

script error  fig.xps:3: XPP is waiting for a mouse drag (a rectangle or a
line) and the script has nothing to give it: add a "drag x1 y1 x2 y2" line
after this one, or "drag ?" to leave it to a person

A script run by hand waits for the person to click, and then carries on. A click where a drag is wanted (or the other way round), and a click or drag with no mouse wait before it, are errors too. Inside try they are caught like any other failure.

5. Saving pictures: shot

shot writes the picture straight to a file. It does not open any dialog, so a script keeps working if a menu later gains or loses an options form.

shot fig1.ps                         # the plot window, as Postscript
shot fig1.svg                        # ... as SVG (the extension chooses the format)
shot fig1.ps fontsize=24 linewidth=25    # options for this file only
shot auto diagram.ps                 # the AUTO bifurcation diagram

The options are color=0|1, orient=landscape|portrait, fontsize=N, font=Name and linewidth=X. They apply to that one file; the settings go back to what they were afterwards (unlike the Postscript dialog, whose settings stay changed for the rest of the session). The files are identical to those written through Graphic stuff -> Postscript or AUTO's File menu. If there is no AUTO diagram yet, shot auto stops with a message and creates no file.

6. AUTO

keys f a              # open the AUTO window
autokeys r s          # Run -> Steady state
auto list             # show the labelled points and their numbers
auto goto HB 1        # select a point as Grab + Enter would
autokeys r p          # Hopf point menu -> Periodic

auto goto forms:

Line Selects
auto goto HB 1 the first point of that type (BP EP HB LP MX PD TR UZ); HB 2 the second; HB -1 the last
auto goto lab 5 the point with label 5
auto goto first / last the ends of the diagram
auto goto HB 1 branch -2 search only one branch, numbered as auto list shows (periodic branches are negative)

The point's parameter and state values are loaded and the next AUTO command continues from it. "Second" means second in the order the points were computed. Use auto list to see the order.

Saving the diagram uses AUTO's own File menu. Its Postscript item asks for the options first (the same form as Graphic stuff -> Postscript) and then for the file name; SVG asks only for the name:

autokeys f p          # AUTO File -> Postscript
ok                    # accept the options (or: ans ||24||25)
ans diagram.ps
autokeys f v          # AUTO File -> SVG
ans diagram.svg

A script written for the older AUTO Postscript, which asked only for a file name, needs the extra ok line (without it the file name is taken as the answer to the options form and the script stops with "the script ended while a menu or dialog is still open").

The Grab keys also work through autokeys, starting from the first point: tab (next labelled point), pgup/pgdn (next/previous labelled, no wrap), home/end, left/right (one point), up or down followed by b e h l m p t u (next/previous point of a type), and enter to select. For example, autokeys g tab tab left enter. This is the only way to reach a point that has no label.

7. The data browser

The data browser (the Data button in the top row of the main window) shows the stored solution as a table. A script can open it, move around in it, and use its commands. Run something first, since there is nothing to show until there is a solution.

keys i g
browser open                  # the Data button
browsekeys down down pgdn     # move around
browsekeys f                  # Find: opens a form
ans Variable=x|Value=0.5      # go to the row where x is closest to 0.5
browsekeys g                  # Get: that row becomes the initial conditions
browser close                 # the Close button

browser open raises the browser if it is already open. browser close, browsekeys and the other browser commands stop the script with a message if the browser is not open. browsekeys takes the same tokens as keys (section 3), but sends them to the browser. These are its keys, and each is also a button on the browser window:

Key Button What it does
up down Up, Down Move one row.
pgup pgdn PgUp, PgDn Move one page of rows.
left right Left, Right Scroll the columns.
home end Home, End Go to the first or last row. Home also clears the selected range of rows (below).
s e First, Last Mark the current row as the first or last row of a selected range. Write and Restore use the range.
f Find Form Find Data with the fields Variable and Value. Moves to the row, from the current row down, where the variable is closest to the value.
g Get Makes the current row (time and variables) the initial conditions.
r Restore Restores the selected rows as the current solution (as the main menu Restore does).
w Write Writes the selected rows to a file. File selector (*.dat): ans out.dat.
l Load Reads a data file into the browser. File selector: ans out.dat.
p u Replace, Unrepl Replace asks two questions, the variable and then the formula, so it needs two ans lines. Unrepl undoes the last replace.
t Table Form Tabulate with the fields Variable, Xlo, Xhi and File: writes a lookup table.
a d Add col, Del col Add col asks for a name and then a formula (two ans lines). Del col currently only shows an error box in XPP, which stops the script.
esc Gives the keyboard back to the main window. The browser stays open.

As with a person at the keyboard, a key goes to the window the pointer is over (or the one with the keyboard focus). A script does not have this problem: browsekeys always goes to the browser, and keys always goes to the main window.

8. The array plot

The array plot shows a stored solution as an image (rows are times, columns are the variables Column 1, Column 1+1, ...). It opens from Viewaxes → Array, which asks for its settings in the Edit arrayplot form. After that its buttons are scripted with aplot.

keys i g
keys v a                                  # Viewaxes -> Array: the Edit arrayplot form
ans Column 1=v|NCols=20|NRows=100         # first variable, number of columns and rows
aplot fit                                 # rescale Zmin and Zmax to the data
aplot gif                                 # file selector
ans array.gif
aplot close

The fields of the Edit arrayplot form are Column 1 (the name of a variable; any other name is an error box), NCols, Row 1, NRows, RowSkip, Zmin, Zmax, Autoplot(0/1) and ColSkip. The buttons:

Line What it does
aplot edit The Edit arrayplot form again.
aplot fit Rescales Zmin and Zmax to the data and redraws.
aplot redraw Redraws.
aplot range Form Array range saving with the fields Basename, Still(1/0) and Tag(0/1), then a range integration that saves the array plots.
aplot print Form Print arrayplot with the fields Filename, Top label, Side label, Bottom label and Render(-1,0,1,2). Does nothing if the plot has not been defined.
aplot gif Saves a GIF. File selector: ans array.gif.
aplot surface Makes a surface plot from the array plot.
aplot close Closes the array plot window.

aplot stops the script with a message if the array plot is not open. Dragging in the plot window to scroll the rows has no script form: set Row 1 in the aplot edit form instead.

9. Loops

for a in 0.5 1.5 2.5            # a list of values (words, numbers, "quoted text")
  set a=$a
  keys i g
  shot fig_$a.ps                # $a also works inside file names and ans lines
end

for k = 0:0.5:2                 # start:step:stop (step 1 if left out); 0, 0.5, 1, 1.5, 2
  ...
end

repeat 3                        # no variable
  ...
end
  • Variables: $a or ${a} (use the braces when a letter follows: ${a}x). $$ is a literal $. Loops can be nested (up to 8 deep), and an inner loop can use an outer variable.
  • Checked before anything runs: a loop is expanded when the script is loaded, so every iteration is syntax-checked first. A missing end, an undefined $name, a range with step 0, or a loop that expands to more than 200,000 lines is an error at load time (exit status 2).
  • Failures name the iteration: fig.xps:7: auto goto: the diagram has only 1 HB point [loop: a=1.5].
  • Values are fixed when the script loads. A loop cannot depend on a result computed during the run (for example, "for each Hopf point found").

10. Carrying on after a failure: try

Without try, the first command that fails stops the script. Wrap a block in try when a failure is expected and the rest of the script should carry on (this example is for a model with a parameter tau):

for tau in 1 1.5 2 2.5 3
  set tau=$tau
  try
    autokeys r s
    auto goto HB 1                # there may be no Hopf point for some values of tau
    autokeys r p
    shot auto diagram_$tau.ps
  else
    msg "tau=$tau: skipped ($error)"
  end
  autokeys f r                    # clean up on both paths
  ans y
end

If every command between try and else works, the else part is skipped. If one fails, the rest of the try part is skipped, the else part runs, and the script continues after end. The else part is optional (try ... end just skips the block silently).

  • What is caught: anything that would otherwise stop the script while it runs: auto goto with no such point, an unknown name in set, a file shot cannot write, a wrong answer to a prompt, and an XPP error box (the box is not shown).
  • What is not: mistakes in the script itself (a typo, a missing end) are still found when the script is loaded, before anything runs. quit and anything that makes XPP itself exit are not caught.
  • $error in a msg (or pause) text is the message of the failure that was caught, for example auto goto: the diagram has only 1 HB point.
  • Nesting: try blocks can be nested and can sit inside loops or contain them. A failure in an else part is caught by the enclosing try, if there is one.
  • Cleaning up: the failed command may have left a menu, form or message box open. XPP presses Esc until it is back at the top level, and for a form (which has no keyboard cancel) it also presses the form's accept key, which keeps the values as they were. If it cannot get back to the top level, the script stops with an error.
  • The log and the exit status: each caught failure is written to the terminal as script caught file.xps:5: ... [loop: tau=2.5], and the script ends with a summary line. Under -scriptexit a script that finished but caught something exits with status 3, so a batch job can tell "everything worked" (0) from "finished, but some passes were skipped" (3).

11. Recording a script

XPPAUT can write the script for you while you work. Do the task once by hand, then replay it, edit it, or send it to a colleague.

  1. File → recOrd script (key o). A file selector asks for the name; the default is the model name with .ode replaced by .xps (osc.ode → osc.xps). If the file exists you are asked before it is overwritten.
  2. XPP asks Start with the current parameters? If you say yes, the script begins with set lines for every parameter and initial condition, so that it does not depend on how XPP was set up when you replay it. If you say no, only your changes are recorded.
  3. Work as usual. The File menu entry now reads stop recOrding.
  4. Choose it again to stop. The keys that stopped the recording are not written. Quitting XPP also closes the file. The file is kept up to date as you go, so a crash does not lose the last lines.

The file is an ordinary script. Run it with File → Do script, or xppaut model.ode -script osc.xps.

What is written

The recorder writes what you meant, not every key, so that the script still works when you replay it.

You do The script gets
Press menu keys, or click menu items keys i g. Consecutive keys are collected on one line. Menu items clicked with the mouse are written as their hot key.
Answer a dialog A comment with the name of the dialog, then ans, ok or cancel. Forms are written by label and only the fields you changed (ans X Lo=-5); an untouched form is ok. Keys typed into a dialog are not written as keys.
Click or drag in the plot window (placing text, zoom, mIce) click x y or drag x1 y1 x2 y2, in data coordinates. The numbers are those of the pixel you pointed at, so expect values like -1.0023 rather than -1; round them if you like.
Edit a parameter or initial condition in its box, or move a slider set mu=3, only when the value changed. Typing in the box is not written, only the value that was entered.
Press Go in the parameter window keys i g
Press keys or buttons in the AUTO window autokeys r s
Pick a point in the AUTO diagram with Grab auto goto lab 5, or by type and number if the point has no label (auto goto HB 1 branch 1). The keys that moved along the diagram are not written.
Open or close the data browser; use its keys or buttons browser open, browser close, browsekeys down f
Press a button of the array plot window aplot edit, aplot fit, ...
Scroll the array plot with the mouse A comment line saying that it happened. It cannot be written as a command.

In recorded keys lines a capital letter or a punctuation mark is written in quotes (keys "A"), which types it exactly.

A short recording (the comments in the header and the dialog names are written for you):

# XPPAUT script recorded Fri Nov 20 03:08:50 2026
# model: vdp.ode
# Edit freely.  Run it with File -> Do script, or:  xppaut model.ode -script this_file.xps
set mu=3
keys i g
keys w w
# Window
ans X Lo=-5
keys u t
# total
ans 40
keys esc
browser open
browsekeys down down pgdn
browser close
# end of recording

What is not written, and editing a recording

  • Timing. A recording has no pauses, so it replays at full speed. Add pause, wait, speed and msg lines by hand to turn it into a tutorial.
  • Aborting a run. Pressing Abort, or Esc during an AUTO run, is not recorded. The replay lets the run finish, which can take as long as the run did before you stopped it. Tighten the AUTO numerics (for example the maximum number of steps) in the script instead.
  • Windows the script cannot open. The ICs, BCs, Delay, Param and Eqns buttons in the top row are mouse only. Parameters and initial conditions you change in their windows are written as set lines, but edits in the BC and delay boxes, clicks in the equation list, window moves and resizes, and rotating a 3D view with the mouse are not.
  • Where the pointer is. A key goes to the window under the pointer, as it does for you. A key is written as browsekeys or autokeys only if the browser or the AUTO window took it; otherwise it is a keys line, which is exactly what XPP did with it.
  • Not while a script runs. Recording is refused while a script is running.

Two environment variables help with testing and demonstrations: XPP_RECORD=file xppaut model.ode starts a recording as XPP starts, and XPP_REC_ECHO=1 also prints each recorded line on the terminal. (XPP_REC_TEST=1 allows recording while a script runs; it is for testing the recorder.)

12. When something goes wrong

A command that cannot work stops the script with the file and line number:

script error  fig.xps:7: auto goto: the diagram has only 1 HB point

Under -scriptexit the exit status is 0 when the script finished cleanly, 1 for a problem while running, 2 for a script that does not parse, and 3 when it finished but a try caught a failure. These also stop a script: a name set does not know; an ans with no dialog waiting (the line before it did not open one); a wrong answer to a yes/no; too many fields; and any XPP error box, and browser, browsekeys or aplot when that window is not open. Two more are errors only with -nopause or -scriptexit: a script that ends with a menu or dialog still open, and a set or auto goto while one is open. Interactively the script simply waits for you to close it. This is why an unattended script can never hang.

13. Examples

1. Set up, run, and save a figure. (Two files: PostScript with a bigger axis font and thicker lines, and SVG.)

set a=2.5;b=0.2;x=1;y=0
set total=40;xp=x;yp=y;xlo=-10;xhi=10;ylo=-10;yhi=10
keys i g                 # run
keys g p                 # Graphic stuff -> Postscript
ans ||24||25             # options form: change fields 3 and 5 only
ans fig1.ps              # file name
keys g v                 # SVG has no options form
ans fig1.svg

2. Phase plane with nullclines, window set through its dialog.

set xp=x;yp=y
keys i g
keys w w                                       # Window/zoom -> Window
ans X Lo=-10|X Hi=10|Y Lo=-10|Y Hi=10
keys n n                                       # Nullcline -> New
keys g p
ok                                             # accept the PostScript options
ans phase.ps

3. A parameter sweep: one figure per value.

set b=0.2;x=1;y=0;total=30
for a in 0.5 1.5 2.5
  set a=$a
  keys i g
  shot sweep_$a.ps                # sweep_0.5.ps, sweep_1.5.ps, sweep_2.5.ps
end

To put several values on one plot, freeze each run. XPP keeps only the last trajectory unless it is frozen. Graphic stuff -> Freeze -> Freeze (keys g f f) opens an Edit Freeze form (Color, Key, Name), which ans or ok fills in. Put one shot after the loop:

set b=0.2;x=1;y=0;total=30
for a in 0.5 1.5 2.5
  set a=$a
  keys i g
  keys g f f
  ans |"a=$a"|                     # Edit Freeze: keep the colour, Key = a=0.5, ...
end
shot sweep.ps                      # all three curves

Use ok instead of the ans line to accept the form as it is. Quote the key ("a=$a"), since an unquoted a=... is read as a field name.

4. Continue a run.

set a=2.5;b=0.2
keys i g
keys i l                 # Initialconds -> Last: continue from where it stopped

5. A tutorial with pauses.

msg "Driven oscillator"
pause "Press Enter to set the parameters"
set a=2.5;b=0.2;x=1;y=0
set xp=x;yp=y;xlo=-10;xhi=10;ylo=-10;yhi=10
pause "Press Enter to run it"
keys i g
msg "The oscillation spirals outward"

Run it normally for the tutorial, and with -nopause to get just the final picture.

6. A bifurcation diagram: first Hopf point and the periodic branch.

keys i g i l i l         # settle on the resting state (AUTO starts from the current state)
keys f a
autokeys r s
auto goto HB 1
autokeys r p
auto list

6b. A diagram for each value of another parameter (build, save and reset on every pass).

keys f a
for rep in 1 2
  set r=1.0;x=1.0               # start every pass from the same point
  autokeys r s
  auto goto HB 1
  autokeys r p
  shot auto diagram_$rep.ps
  autokeys f r                  # AUTO File -> Reset diagram
  ans y
end

In a real study the loop variable would be a model parameter (for tau in 1 2 3, then set tau=$tau). Reset does not restore parameters or initial conditions, so every pass sets its starting values again.

6c. A sweep that survives a pass with no Hopf point (runs as it stands on the Hutchinson model).

keys f a
for r0 in 1.0 2.0 1.2
  set r=$r0;x=1.0               # start the branch of x = 1 at r = r0
  autokeys r s
  try
    auto goto HB 1              # no Hopf point if the branch starts beyond r = pi/2
    msg "r0=$r0: Hopf point at r = 1.5708"
  else
    msg "r0=$r0: no Hopf point  ($error)"
  end
  autokeys f r
  ans y
end

The pass with r0=2.0 fails and is caught; the other two finish, and the script exits with status 3.

7. Load a stored parameter set (from a set line in the ODE file).

keys f g                 # File -> Get par set
keys a                   # the first set in the list
keys i g

8. Unattended, for a batch job.

xvfb-run xppaut model.ode -script fig.xps -scriptexit
echo $?                  # 0 = finished, 1 = a command failed, 2 = the script had a typo,
                         # 3 = finished, but a try block caught a failure

9. Several starting points with the mouse (Initialconds → mIce). mIce needs a phase plane, so the plot is set to one first. Auto-freeze keeps every run on the plot (without it only the last run stays). Each click is a starting point; keys esc ends mIce, as it does for a person.

set a=0;b=0.2;total=20;xp=x;yp=y;xlo=-3;xhi=3;ylo=-3;yhi=3
keys g f a                # Graphic stuff -> Freeze -> Auto-freeze (a toggle)
keys i i                  # Initialconds -> mIce
click 1 1                 # a run from x=1, y=1
click -1 0                # a run from x=-1, y=0
click 0 -2                # a run from x=0, y=-2
keys esc                  # end mIce
shot mice.ps              # all three runs

10. Start a run from a point on the last trajectory (data browser).

set a=2.5;b=0.2;x=1;y=0
keys i g
browser open
browsekeys f
ans Variable=x|Value=0.5      # the row where x is closest to 0.5

11. An array plot of a simulation, saved as a GIF. (For a model with variables v1 ... v20, say a chain of cells; use the name of your first variable.)

14. Tips and current limits

  • To find the keys for a task, do it by hand once and note the capital letters in the menu names.
  • AUTO takes its ranges from the model's @ options (parmin, parmax, autoxmin, ...). Put them in the ODE file, or add a set line.
  • keys i g i l i l is useful before AUTO: it runs the simulation long enough to reach rest.
  • If a keys line seems to do nothing, check that the ans after it matches what actually opens.
  • Mouse waits in the plot window are covered by click and drag (section 4). Not available yet: mouse actions elsewhere (the AUTO window, rotating a 3D view, scrolling the array plot), the other buttons in the top row (ICs, BCs, Delay, Param, Eqns), and writing print output to a file.
  • The quickest way to find the keys for a task is to record it: switch on File → recOrd script, do the task by hand, and read the file (section 11).
